## 범위와 판정

여섯 페르소나에 대해 실제 앱 HTTP 경로와 실제 OpenAI 호출로 합성 대화를 진행했다. 대화와 피드백 모두 `gpt-6.1-sol`, reasoning `low`, 출력 한도 1536/4096을 사용했다. 평가자가 매 응답을 읽고 다음 사용자 발화를 작성했다. Supabase와 Langfuse는 이 평가에서 연결하지 않았다.

각 대화는 14~15회 사용자 발화, 총 29~31개 메시지다. 처음 목표는 20회였으나 성급한 결단 요구에 상대가 종료 의사를 밝혀 사과하고 끝냈다. **여섯 명 모두 20턴을 통과했다는 결과가 아니다.** 종료 의사를 무시해 횟수를 채우지 않았다. 이 범위에서 정정 기억, 경험의 당사자 구분, 미해결 의문 유지, 거절과 수습, 피드백의 근거 일치를 확인했다. 사람과 구분할 수 없는 자연스러움이나 더 긴 모든 상황의 품질을 보증하지 않는다.

## 실제 표면 QA

자료 루트는 `.omo/qa/persona-long-2026-10-15/static-cache-v1/<personaId>/`다. 각 `state.json`에는 해시가 있는 원문과 전체 HTTP 응답, `calls/`에는 실제 전송 payload·사용량·응답, `*-receipt.json`에는 누적 예산과 임시 서버 정리 결과가 있다. 원문은 합성 평가용이며 일반 사용자 기록이 아니다.

## 발견한 문제와 수정

1. **고정 페르소나 설명의 캐시 경계 누락.** 이전 D1은 매 호출 1,259토큰만 재사용했다. Sol 역할극 요청만 고정 지침·인물 카드를 명시적 캐시 블록으로 분리하고, 전체 동적 대화 기록은 그대로 전달한다. `prompt_cache_options.mode=explicit`로 바뀌는 대화 내용의 불필요한 캐시 쓰기를 막았다. 다른 모델과 피드백 경로는 기존 payload를 유지한다. 공식 동작 근거: https://developers.openai.com/api/docs/guides/prompt-caching
   - 김시현 두 번째 호출: 입력 5,331, 캐시 읽기 3,957, 캐시 쓰기 0, 출력 80토큰. 실제 추정 비용 $0.0039437.
   - 오유진은 동일 고정 블록에서도 캐시 미스가 발생해 더 비쌌다. 모든 호출의 할인이나 고정 비용을 보장하지 않는다.
   - 회귀 red/green 및 전체 시험 증거: `.omo/evidence/sol-static-cache/verification.md`와 인접 로그.
2. **한서준 시작 발화가 사용자 행동을 발명.** 사용자 발화 전인데 사용자가 밥값 정산을 챙겼다고 말했다. `initialDynamicPromptFor`에 사용자 과거 행동·발언·감정·경험을 임의 설정하지 말라는 지침을 추가했다. 이후 동일 조건 시작 3회에서는 사용자 행동 발명이 없었다. `.omo/qa/persona-long-2026-10-15/opening-grounding-v1/`의 `run-0..2.json` 및 `calls/` 참조. 3회는 제한된 재검증이며 확률적 모델의 완전한 방지는 아니다.

긴 대화 6회는 캐시 수정 후·시작 지침 수정 전의 소스 해시다. 마지막 시작 지침 변경은 시작 응답 3회로 따로 확인했다. 최종 소스로 모든 긴 대화를 다시 실행했다고 주장하지 않는다. 역할극 중간 응답과 피드백 조립은 마지막 변경에서 수정하지 않았다.

## 운영 배포: 차단 상태

운영 대상은 `gospel-conversation-simulator.onrender.com`, Render 서비스 `srv-d8325cbtqb8s73bjfdo0`, GitHub `leewish03/persona_gospel`의 `master` 자동 배포다. 현재 배포 SHA는 `f98a88a7e5d43ce3f7e85f6c079e70cabc0cb41b`다. `/healthz`는 200이지만 데이터베이스 건전성을 보증하지 않는다.

Render에 설정된 Supabase 프로젝트 `wyqpcldqlyrqbppjdhhp`가 일시중지돼 있다. 대시보드는 데이터가 보존돼 있다고 표시한다. 재개를 시도했으나 사용자 계정의 무료 활성 프로젝트 2개 한도 때문에 거부됐다. 다른 프로젝트를 임의 중지하거나 유료 요금제를 결제하지 않았다. 사용자에게 사용하지 않는 프로젝트 하나를 직접 일시중지해 달라고 요청했다.

운영 앱은 Supabase 실패 시 임시 JSON 저장으로 돌아갈 수 있어 현재 상태로 재배포하면 최근 임시 기록이 사라질 위험이 있다. **코드 push/운영 재배포/운영 프롬프트 게시/운영 설정 변경은 아직 하지 않았다.** DB 재개 후 기존 운영 프로세스의 저장 상태와 기록 보존을 확인한 다음 배포해야 한다. 필요 시 안전한 백업을 먼저 확보한다.

Langfuse의 두 production 프롬프트는 모두 버전 1이다(역할극 523자, 피드백 1,349자). 검증한 로컬 프롬프트와 다르므로 코드 배포만으로 개선이 모두 적용되지 않는다. DB 복구 후 저장된 모델 설정을 확인하고, 검증된 프롬프트를 롤백 가능한 버전으로 게시하며, 운영 모델·프롬프트 출처와 로그인·대화·피드백을 확인해야 한다. 이 배포 후 확인은 아직 미실행이다.
