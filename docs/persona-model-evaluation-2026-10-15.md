### Task 9 최종 결과와 정산

Task 9의 mini-low/D1-main은 사용자 24턴, 피드백 HTTP 200과 정식 피드백 저장까지 완료됐다. 필수 소개(U5)·정정(U12)은 전달됐지만 회상(U23)은 전달되지 않아 2/3에 그쳤다. 평가 도구가 현재 회상 턴을 이미 지난 턴으로 잘못 판단했다. 회상 질문이 실제 전달되지 않았으므로 이 사건으로 후보의 기억 능력 통과·실패를 추론하지 않는다. 실행 exit 0이나 유효한 피드백도 coverage 합격을 뜻하지 않는다. 전체 대화의 독립 관찰 검토는 품질 관찰용이며 누락된 평가 범위를 채우거나 순위를 정하지 않는다.

독립 블라인드 검토는 관찰된 한 후보·한 합성 대화에서 인물 연속성 2/5, 연습·피드백 유용성 2/5로 평가했다. 시뮬레이터 사용자가 자신의 상담 일정을 인물의 경험으로 잘못 돌렸고, 인물은 이를 반복해서 받아들였다. 최종 피드백의 인용 6개는 모두 실제 사용자 발화와 정확히 일치했지만, 이 경험 주체 혼선을 놓치고 이미 수행한 질문을 다음 과제로 반복했다. 이는 누락된 회상 질문과 별도로 관찰된 제품 품질 한계다. 다만 한 대화의 기술적 관찰이며 후보 순위·전체 품질 합격·교육 효과를 뜻하지 않는다. 회상·명시적 거절 등 전달되지 않은 질문의 성능은 여전히 미검증이다. 근거: .omo/evidence/purposeful-persona-training/task-9-blind-review.md.

### 설정·회귀 검증 및 운영 한계

실제 @langfuse/client 5.3.0과 로컬 원격 프롬프트 fixture로 설정 시나리오 7개를 검증했다. 저장 설정 우선, 원격 프롬프트 source/version, 원격 비활성·조회 실패 시 파일 fallback, 잘못된 모델 오류 후 기록 보존·관리자 수정·재시도, 로컬 파일 변경의 시작 시점 재로딩을 확인했다. 원격 fixture 버전 81은 운영 버전이 아니다. 실제 trace metadata의 source/version/model과 공급자 요청의 추론·출력 상한을 각각 검증했고, 이 격리 검증에서 추적 전송은 로컬 수집기로 대체했다.

### 당시 기본값 결정

초보 성도·청년의 전도 대화 연습용 신규 기본 설정은 `gpt-6-luna`, reasoning `low`, 최대 출력 768토큰이다. 피드백은 기존 `gpt-5.4`/medium/2600을 유지한다. 기존 환경변수와 저장된 관리자 설정을 자동으로 바꾸지 않는다. 로그인과 인증·소유권 검사는 유지한다.

Luna와 Haiku 5.5 모두 사용자의 API 계정 모델 목록에서 접근 가능함을 확인했다. Gemini 키가 없고 사용자가 제외하도록 지시하여 Flash 실호출과 공급자 추가는 하지 않았다. Haiku는 관리자에서 선택 가능하지만, 이번 대화 표본의 내부 설명·이름표 노출 때문에 기본 모델로 추천하지 않는다.

공식 단가(표준 텍스트, USD/100만 토큰): [Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)는 입력 0.10, 캐시 읽기 0.01, 캐시 저장 0.125, 출력 0.50이다. 272K 초과 입력에는 전체 요청에 높은 단가가 적용된다. [Haiku 5.5](https://platform.claude.com/docs/en/models/haiku-5-5/overview)는 100K 이하 입력에서 입력 0.10/출력 0.50, 초과하면 0.50/2.50이다. 해당 경계와 캐시 비용을 서버 계산에 반영했다. Haiku의 sampling·thinking 호환성은 [마이그레이션 문서](https://platform.claude.com/docs/en/models/haiku-5-5/migration-guide)에 맞췄다.

### 이전 기록: 엔지니어링 변경

- 보통 40~120자, 1~2문장. 직접 질문에 답할 때만 3문장까지 허용한다. 768토큰은 추론을 포함한 안전 상한이며, 답을 그 길이까지 채우라는 목표가 아니다.
- 같은 장벽을 매 턴 재진술하거나 공감 뒤에 새 고민을 반드시 추가하는 상충 지침을 제거했다.
- 장소 단어가 최근 대화에 없다는 이유로 카페·커피를 다시 말하게 하던 로직을 삭제했다.
- 일반 질문의 예비 반응에서 구원·하나님 사랑을 제거했다. 신앙 주제를 사용자가 자연스럽게 열 기회를 남긴다.
- 경청 목표라는 이유만으로 복음 설명에 자동 방어하지 않는다. 실제 압박 여부와 앞선 경청 맥락을 구분한다.
- 사용자와 인물의 경험·약속·사과 주체를 구분한다. 이해받는 것과 믿음에 동의하는 것을 분리하며 자동 회심을 보상으로 주지 않는다.
- OpenAI의 명시적 `none`을 생략해 기본 추론이 켜지던 요청 처리와 캐시 저장 토큰 집계를 수정했다. Haiku 5.5는 지원하지 않는 sampling 값을 보내지 않고, 빈 답변에 자동 유료 재호출하지 않는다.
